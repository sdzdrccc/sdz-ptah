## 0 · 开源前提：拆分两条路线

- **问题**：
  - 当前主路线调用宿主工具 `agnes_aigc__image_to_image`，外部用户 clone 仓库后没有该入口。
  - 第一升级候选 ModelScope 免费推理需实名 + 绑定阿里云，且非商用。
  - 结果：项目对外没有一条「任何人照 README 就能跑通」的路线。
- **修改建议**：
  - 0 节与 2.9 节明确区分：
    - **维护者路线**：宿主 i2i / ModelScope，用于快速实验。
    - **项目默认路线**：开放权重模型（见 A / B / 1），无需任何账号。
  - 后端抽象为适配器接口（如 `backends/<name>.py`，统一入参：prompt、negative、参考图列表、seed、size；统一出参：图片 + 元数据）。宿主 i2i 只是其中一个适配器。
  - 2.1 对比表新增一列「外部可复现」（是 / 需账号 / 否）。
- **验收**：README 中默认路线从安装到出第一张图不依赖任何私有工具或实名账号。

## 一、现有方案的修正

### 1. Qwen-Image-Edit：区分「权重许可」与「推理服务条款」

- **现状**：2.1 第 3 行、2.4.1、2.4.3 写「明确非商用」。
- **修正**：
  - 「非商用」是 **ModelScope 免费推理服务** 的条款；Qwen-Image-Edit 系列（含 2511）与生成系 2512 的**权重为 Apache-2.0**。
  - Qwen-Image-2.1 为研究许可、商用需另签——选版本时不要混用。
  - 2511 官方宣称：减轻图像漂移、提升人物一致性、集成 LoRA 能力——与本项目需求直接对口。
- **新增接入方式**（2.4 下拆子节）：

| 接入方式 | 许可 / 条款 | 门槛 | 状态 |
|-|-|-|-|
| ModelScope 免费推理 | 服务条款：非商用、动态限流 | 实名 + token | 接口已实测，出图待验证 |
| 阿里云百炼付费 API | 按量计费，商用以服务条款为准 | 阿里云账号 | 待验证 |
| 自部署全精度 | Apache-2.0 | 20B，需大显存云 GPU | 待验证 |
| 社区量化版（GGUF / Nunchaku 4-bit 等） | 继承 Apache-2.0 | 显存需求下降，具体值待实测 | 待验证 |

- **同步修改**：2.4.3 对比表「商用」一行改为「权重可商用；免费推理服务非商用」；9.1 模型许可表补此条。

### 2. IP-Adapter FaceID / InstantID 不适用于动漫角色

- **现状**：2.1 第 8、9 行与 2.5 把它们列为身份锁定手段。
- **问题**：两者依赖 InsightFace 真人脸检测与识别，输入动漫图常直接报「No face found」；即使检出，识别向量对动漫角色判别力很弱。另外 InsightFace 预训练模型的许可**待核实**（通常为非商用研究许可）。
- **修正**：
  - 身份锁定改为：IP-Adapter **Plus**（非 FaceID，参考整图）+ 角色 LoRA，或以三视图 / 设定图作参考。
  - 2.1 第 9 行「ComfyUI + InstantID」改名为「ComfyUI + IP-Adapter Plus + ControlNet」，InstantID 降为备注。
  - 5.1 风险表新增「真人脸模型对动漫无效」。

### 3. Flux 负向词

- **修正**：2.1 第 10 行「负向词 有」改为「原生无（蒸馏模型），需额外手段」；2.6 能力边界同步。

### 4. GTX 1660 SUPER 的 fp16 风险

- **修正**：2.5 本机基线补一条——16 系显卡跑 SD 常见 fp16 黑图 / NaN，需全精度或部分全精度运行，显存占用上升；「6 GB 可跑 SD1.5」改为「待实测」，写入 8.1 待验证实验。

### 5. Midjourney / Niji 不能作后端

- **修正**：2.1 第 6 行与 2.7 注明「无官方 API，自动化调用违反服务条款」；定位改为「仅人工竞品对照」，不进入适配器列表。

### 6. 商业 API 补全

- **修正**：2.1 第 5 行与 2.7 补以下平台，能力与条款均**待验证**：

| 平台 | 关注点 |
|-|-|
| Gemini 图像模型 | 多参考图编辑、身份保持；动漫画风稳定性 |
| OpenAI gpt-image | 参考图编辑；动漫画风与内容政策 |
| 火山引擎 Seedream | 国内可用；多参考图；商用条款 |
| NovelAI | 动漫专用模型；有 API；新版本角色参考能力 |

- 定位保持「竞品参照 / 长尾补位」，作为可选适配器，不作默认路线。

## 二、新增方案

### A. 动漫专用 SDXL 底模（建议作为项目默认路线）

- **为什么**：现在只写了「SDXL 二次元基座」，没点名。对动漫头像来说这条路线画风最稳、生态最全（Danbooru tag、ControlNet、IP-Adapter、LoRA 齐全），且 seed / 负向词 / 版本锁都有，可完全复现。
- **候选与许可**：

| 模型 | 特点 | 许可 | 随仓库分发 |
|-|-|-|-|
| Animagine XL 4.0 | 默认参数宽容 | CreativeML Open RAIL++-M（有使用限制条款） | 否，脚本下载 |
| Illustrious-XL | LoRA 生态最大，原生高分辨率 | **待核实** | 否 |
| NoobAI-XL | booru tag 覆盖最深 | fair-ai-public-license-1.0-sd；有评测称不可商用，**待核实** | 否 |

- **显存**：8 GB 较从容；6 GB 边缘（配合 fp16 问题，见修正 4）。
- **写入位置**：2.1 新增一行（简易度 ★★★），新增 2.x 小节；9.1 许可表逐项列示。
- **待验证**：三者在同一组 brief 上的横评（风格闸门、`pass@4`、96px 可读率）。

### B. Neta Lumina

- **为什么**：基于 Lumina-Image-2.0 的动漫微调，文本编码器为 Gemma2，能理解 tag、自然语言、中英日混写——和现有「中文 `original_prompt` + 英文 `enhanced_prompt`」衔接最自然。官方公开了权重、训练流程与部分数据。
- **许可**：**待核实**。
- **待验证**：显存需求、身份参考能力（是否需配合 Edit 模型）、白底头像下的风格闸门表现。
- **写入位置**：2.1 新增一行；2.x 小节。

### C. 两段式「身份 → 画风」

- **为什么**：文档核心矛盾是「i2i 锁身份、锁不住画风」。把两件事拆开：
  1. **身份步**：Qwen-Image-Edit 或宿主 i2i，按参考图出身份正确、构图合规的图。
  2. **画风步**：动漫 SDXL 底模（A）+ 风格 LoRA 做低重绘强度 img2img（建议从 denoise 0.25–0.4 开始实测），统一线条、上色与阴影。
- **附带收益**：可修正细节漂移（如脸颊闪电纹由深褐描边变亮黄）。
- **风险**：denoise 过高会把身份冲掉——需用 F 的属性 tagger 做「画风步前后身份五项」对比。
- **写入位置**：2.1 作为「组合方案」单列；4.1 流程图 S2 拆成 S2a / S2b；3.6 后处理表同步。

### D. 固定构图模板 + ControlNet

- **为什么**：眼位越界、角度误判都是生成期构图不确定导致的；现在只能靠裁切事后补偿。
- **做法**：
  - 准备头肩构图模板（深度图 / 姿势图 / 线稿），正脸 `eye_center_y` 预设约 0.31、侧脸约 0.40，留白与肩线按 3.2 数值。
  - 生成期用 ControlNet 约束，构图从「事后补偿」变成「事前确定」。
  - 进阶：用 VRoid 等 3D 模型渲染正脸 / 侧脸 / 3/4 侧，转线稿或深度作约束，多角度稳定。
- **写入位置**：3.2 「生成时脸占比 38%–48%：升级后启用」改为指向本方案；4.3 ControlNet 行补模板来源。

### E. 云 GPU 自部署作为正式评测路线

- **为什么**：本机 6 GB 是硬约束，但 A / B / C / 1（自部署）和角色 LoRA 训练都需要更大显存。按小时租 24 GB 卡（AutoDL、RunPod 等）做评测，成本可控。
- **修改**：附录 D.3 的 Serverless GPU 提升为 2.1 正式一行；P3 升级评估写明「在云 GPU 上做横评」。
- **待验证**：单图耗时、单次评测成本、镜像可复现（固定依赖与模型版本）。
