## P-A · 影响结论（必须改）

### 1. 「i2i 画风锁不住」需修测量后复评

- **位置**：0 节第 2 条；2.2 节「画风锁定：失败」与结论段；5.1「画风不可控」
- **问题**：实测 `raw_quality` 55 分中，style 0（−20）来自纯白底推爆指标，angle 0（−10）来自黑瞳孔 sat 14–21 < `SAT_MIN=60` 致双眼配对失败——C.2 自己已定性为「属检测限制」。两项都是测量问题，修正后同图预计约 85 分，真实不合规只剩眼位越界。
- **修改**：
  - 0 节与 2.2 节结论改为「当前测量下画风判定为失败，主因是风格闸门口径；需修测量后复评」，删去「但它锁不住画风」的定论语气。
  - 新增「测量修正后复评」小节：同一张图（订单 `20261123-100911`）修测量前 / 后两套分数并列。
  - 5.1「画风不可控」与「风格闸门与纯白底冲突」两行合并或明确先后：先确认后者，再判断前者是否成立。
- **验收**：复评分数写入附录 C.2；结论表述与分数一致。

### 2. 眼位越界是裁切未生效，不是生成问题

- **位置**：3.2 节裁切规则；C.2「眼位 0.393/0.408 越界属真实不合规」；附录 B `crop`
- **问题**：附录 B 中 `crop.zoom=1.0`、`candidates=1`，即该图实际未被裁切；3.2 的裁切只约束「脸占比 0.62 + 双眼中点为锚」，没有把眼位作为求解目标。
- **修改**：
  - 3.2 裁切规则改为**联合求解**：脸占比 ≈ 0.62 且正脸 `eye_center_y` ≈ 0.31（侧脸 ≈ 0.40），约束冲突时以眼位优先、脸占比落在 0.34–0.82 内即可。
  - 补「裁切未生效（zoom=1.0）」的原因排查：是脸框未检出、还是规则判定无需裁切。
  - C.2「属真实不合规」改为「当前裁切下不合规，联合求解后待复测」。
- **验收**：同一张图按新裁切规则输出 2–3 个候选，记录各自 `eye_center_y`。

### 3. i2i 结论证据只有 1 张图

- **位置**：0 节第 1 条「唯一同时成立的路线」；2.2 验证状态；2.9 选定理由
- **问题**：全部 i2i 结论来自 1 次调用、1 张产出，无法区分偶然与稳定。
- **修改**：
  - 0 节「唯一同时……成立」改为「在单次实测中……成立，待小批量基线确认」。
  - 新增「小批量基线」任务（建议放 P0 出口或 P1 入口）：同参考图、同 prompt 跑 8–12 次，记录身份五项命中率、各风格指标均值 / 方差、`raw_quality` 分布。
- **验收**：附录 C 新增 C.4 基线统计表。

### 4. 构图指标计算时机冲突

- **位置**：1.3 节提示框「构图类指标一律在裁切后计算」；3.4 `raw_quality` 构图 30 分；4.2 S3（裁切前）
- **问题**：S3 在裁切前就给 `raw_quality` 打构图分，与 1.3 原则直接矛盾；也可能是实测构图拿了满分 30 却仍需裁切的原因。
- **修改（二选一，写明决定）**：
  - A. `raw_quality` 去掉构图维度（权重重分配到面部 / 风格 / 角度），构图只在 S5 判定；
  - B. 保留但改名为「可裁切性」：判定「是否存在合规裁切框」，而非原图构图是否合规。
- **验收**：1.3、3.4、4.2 三处表述一致。

### 5. 预算与产出目标不一致

- **位置**：1.2「主图 + 3–6 张备选」；3.8「每单预算默认 10 张」；5.1「预算 ≤12 次/需求」；6.1「单需求调用次数 ≤ 12」
- **问题**：10 与 12 两个口径并存；i2i 一次 1 张，按 `pass@4 ≥ 70%` 估算，凑齐 1 主 + 3–6 备选的期望调用量可能超出 10。
- **修改**：
  - 统一为一个数字，并写明是「张」还是「次」（i2i 下两者相等，升级后端后可能不等）。
  - 增加一行推算：按目标 `pass@1` 估算达成 1+3 张所需的期望调用数，据此定预算；或把 1.2 的备选数下调为 1–3 张。
- **验收**：四处数字一致，且有推算依据。

### 6. 「占比」口径需统一

- **位置**：1.3 `face_ratio` 0.34–0.82；3.2「生成时脸占比 38%–48%」「目标脸占比 0.62」；3.4 `subject_share` 0.40–0.985
- **问题**：四个数分别以裁切框、原图、内容框为分母，读者无法比较。
- **修改**：新增「术语与口径表」（建议放 1.3 之后），每个指标写明：分子、分母、计算时机（原图 / 裁切后）、取值范围。
- **验收**：正文中出现的所有「占比」都能在表中查到。

### 7. 哈希值歧义

- **位置**：C.2「1024×1024 PNG，sha256 `F4D228…`」；附录 B `"manifest_hash": "f4d228…"`
- **问题**：同一前缀出现在两个含义不同的字段，看不出是图片哈希还是台账哈希。
- **修改**：附录 B 拆为 `output.sha256` 与 `manifest_hash` 两个字段，各填真实值；大小写统一。

## P-B · 缺失内容（建议新增）

### 8. 角色 IP 版权风险

- **位置**：5.1 风险总表；8 待决问题；2.x 各方案「商用许可」维度
- **问题**：文档只讨论了**模型许可**。参考角色 `satoshi`（红白帽、绿色 L 徽标、脸颊闪电纹）看起来是现成动漫作品角色，属第三方 IP；无论用哪个模型，二创成品都不能商用或对外分发。
- **修改**：
  - 5.1 新增一行「角色 IP 权属」：影响 = 对外交付侵权；缓解 = 内部验证可用、对外须原创角色或取得授权。
  - 8 节新增一条待决：「对外交付是否限定原创 / 已授权角色」。
  - S0 brief 增加字段 `ip_status`（原创 / 已授权 / 第三方仅内部）。

### 9. AIGC 标识与服务合规

- **位置**：4.2 S7；5.1；8
- **问题**：未涉及生成内容标识与服务合规。
- **修改**：
  - S7 增加「写入 AIGC 标识」：显式标识（按平台场景）+ 文件元数据隐式标识；manifest 记录标识方式。
  - 5.1 新增「生成内容标识与服务备案」风险行，依据《人工智能生成合成内容标识办法》（2025-09-01 施行）及生成式 AI 服务相关管理规定——**具体义务需法务确认**。
  - 8 节第 1 条扩展：参考图上传宿主 / ModelScope 的数据留存期限、是否用于训练、删除方式。

### 10. 内容安全

- **位置**：5.1；4.2 S0 / S5；1.4 非目标
- **问题**：参考角色设定为儿童，实测已出现年龄漂移；输入端未限制真人照片。
- **修改**：
  - 新增「内容安全」小节：涉未成年角色禁止性化描述（prompt 编译层拦截）；S5 增加 NSFW 检测，命中直接入废图池。
  - 年龄漂移加入驳回理由码（如 `age_drift`），作为身份一致性子项。
  - 1.4 非目标补充输入约束：S0 拒收真人照片作为参考图（或单独走肖像授权流程）。

### 11. 抠图得主体蒙版（落地第 8 节第 3 条）

- **位置**：3.4 风格闸门；8 节第 3 条；4.4 平台适配
- **问题**：「风格指标改为只算主体区」缺具体做法。
- **修改**：
  - 给出方案：纯白底 → 抠图（如 rembg / 阈值 + 形态学）得 alpha 蒙版 → 饱和度、边缘密度、明度 p50、硬软边比只在蒙版内计算；`near_white_share` 改为蒙版外背景纯净度校验。
  - 4.4 新增透明 PNG 输出档（Discord / Telegram / GitHub 等）。
  - 同步更新 `styles\tv-anime-cel.json` 的阈值说明：标定基于主体区。
- **验收**：同一张图在全图 / 主体区两种口径下的指标并列。

### 12. 风格与身份度量升级

- **位置**：3.4；1.3 `reference_similarity`；5.1「正脸双眼检不出」
- **修改**：
  - **风格档案**：从「通用 `tv-anime-cel`」改为「从本角色参考图主体区提取 + 容忍带」，每角色一份，避免用 TV 单帧标定卡白底头像。
  - **身份分**：`identity: null` 列为 P1 评估项——候选 CLIP / 动漫人脸 embedding（ONNX 版本可不依赖 torch）。
  - **眼睛检测**：评估动漫人脸检测器（如 lbpcascade_animeface + OpenCV）替代 / 补充饱和度找瞳孔；至少把 `SAT_MIN` 对深色瞳孔的失败写入已知限制。

### 13. ModelScope A/B 实验设计

- **位置**：2.9 升级路径「同参考图单次对照」；P3；C.3
- **修改**：
  - 写成可执行实验：同参考图、每组 N=8、固定 seed、同一套闸门（修正后口径）打分；记录限流命中、单图耗时、「魔方」消耗。
  - 预定胜出条件（例：`pass@4` 提升 ≥ 20pp 且身份五项命中率不低于 i2i）。
  - 说明 `MusePublic/Qwen-Image-Edit` 与 `Qwen/Qwen-Image-Edit` 的区别。
  - 2.4.2 中 Edit-2509 / 2511 不在实测模型列表内，标注「可调用性待验证」。

### 14. 评测集与标注细节

- **位置**：P1「200–300 张标注集」；6.2；6.1「96×96 可检出人脸」
- **修改**：
  - 写明标注集来源与成本：按单需求 10 张预算，凑 200–300 张需约 20–30 单，是否单独立预算。
  - 双盲标注增加一致性指标（如 Cohen's κ ≥ 0.6，不达标先修标注指南）。
  - 「96px 可检出人脸」写明用哪个检测器、哪个置信度阈值。
