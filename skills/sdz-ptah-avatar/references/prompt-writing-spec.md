# 提示词编写规范（agent 用）

| 项 | 内容 |
|-|-|
| 版本 | `prompt-spec-v1`（2026-11-26） |
| 适用 | 所有由 agent 编写、交给 `generate.py` 的提示词（网页订单 `prompt_source=manual`、agent 直接调用 `/api/generate`、命令行 `--prompt-file`） |
| 分工 | **agent 写提示词**；**颜色取自参考图实测**；脚本只校验不改写（`check_prompt.py` 自查 + `generate.py` 审计）；网页不检查、不改写 |
| 工具 | `scripts/ref_palette.py`（参考图取色）、`scripts/check_prompt.py`（提示词校验） |
| 上位文档 | `protocol.md` §2.6 编译顺序、§2.6.1 肤色三档、§2.8 正/反向分支、§2.9 审计。本规范与之冲突时以本规范为准，并回改 protocol |

> 原则：**颜色写成可测的数，画风写成具体的手法，构图写成可量的比例。**
> 不用联想词，不用质量堆叠词，不写生成端不认的参数。

---

## 1. 工作流程（每单必走）

1. **看参考图**：确认角色、要保留的标志性特征、参考图本身的朝向与构图，以及需要改成什么（角度、取景、背景）。
2. **取色**：用 `ref_palette.py` 按部位框选取色（第 2 节）。所有颜色都从这一步来，不凭印象写。
3. **定后端**：查第 6 节，确认该模型支不支持负向词、参考图上限是多少、写不写 `<image 1>`。
4. **写正向段**：按第 3 节的七段固定顺序写。
5. **写负向段**：按第 5 节，后端支持就写独立负向，不支持就改写成否定句并入正向段。
6. **自查**：跑 `check_prompt.py`（第 8 节），**有错误（E）不提交**，警告（W）逐条确认。
7. **提交**：写成第 7 节的 JSON，或把正/反向粘进网页。
8. **看图**：出图后人工看。不合格就改提示词重写，**不改阈值、不靠后处理补救**（protocol 第一原则）。

## 2. 颜色：一律按参考图实测

### 2.1 取色方法

```powershell
cd F:\zxc\Project\sdz-ptah\skills\sdz-ptah-avatar
# 先看整体主体色板（自动去黑边、排除四角背景）
py -3 scripts\ref_palette.py --image <参考图> --auto
# 再按部位框选（0–1 坐标相对于去黑边后的有效画面；也可以用原图像素坐标）
py -3 scripts\ref_palette.py --image <参考图> ^
    --skin 皮肤=0.56,0.50,0.80,0.66 ^
    --region 头发=0.47,0.33,0.53,0.46 --region 帽檐红=0.47,0.21,0.85,0.28 ^
    --region 外套蓝=0.48,0.86,0.57,0.99 --region 右眼=0.70,0.30,0.75,0.41 ^
    --json <订单目录>\palette.json
```

- **框选要紧**：每个框只框一个部位的一种颜色，别把相邻部位、背景、其他角色框进来。框完先看输出的次色：
  次色里出现了不该有的颜色（例如头发框里出现黄色），说明框到了别的东西，要缩框重取。
- **皮肤用 `--skin`**：脚本会排除描边黑和眼白，自动给出底色、主暗部、深投影（可能没有）和高光上限，
  并直接给出可以贴进提示词的整句。框要包含脸颊和下颌的暗部，否则取不到暗部。
- **眼睛单独框一只眼**：瞳孔、虹膜和眼白分开看次色。实例：小智 TV 截图实测是深棕黑瞳孔 `#413630` 加白眼白，
  不是此前提示词写的"琥珀棕大眼"——这正是必须实测的原因。
- 取色结果（`palette.json`）随订单保存，作为这份提示词的颜色来源证据。

### 2.2 写法

```
<部位>：<简单色名> #RRGGBB（色相 H°、饱和度 S%、明度 V%）
```

- `#RRGGBB` 和三个数值**都抄 `ref_palette.py` 的输出**，不手算、不估。
  `check_prompt.py` 会重算 hex 的 HSV，偏差超过 2 判错（E9）。
- 色名只用简单、不带联想的词：黑、深棕黑、正红、暗红、白、米白、蓝、深蓝、黄、浅暖粉……
  色名只是帮人读，**以 hex 为准**。
- 允许补充相对关系作辅助（"比白色领口略深""比帽子的红色更灰"），但不能代替 hex。

### 2.3 必须锚定的部位

| 部位 | 要求 |
|-|-|
| 皮肤 | **底色 + 主暗部必填**，深投影按取色结果有就写，最后写"皮肤最亮处不超过 #hex"。固定句式见第 9 节示例 |
| 头发 | 主色必填；有明显暗部色阶时写暗部 |
| 眼睛 | 瞳孔/虹膜色必填；写明眼白和高光数量（TV 赛璐璐通常一点白色小高光） |
| 服装、帽子、配饰 | 每种主要颜色写一个 hex；标志性小件（纽扣、徽标、背带）也要写 |
| 背景 | **单独设计，不从参考图背景取**（参考图背景常是场景）。头像底色是纯色平涂，写一个 hex；用户指定了就用用户的 |

### 2.4 禁用的模糊色词

以下词**在整个正向段里都不能出现**，不管修饰的是皮肤、头发还是别的部位——`generate.py` 的审计不分语境，
出现就拒绝（退出码 2）。词表以 `generate.py` 的 `BANNED_VAGUE` 为准，`check_prompt.py` 直接读取同一份：

> 小麦色、暖调小麦色、暖调皮肤、日晒感、日晒黑、健康肤色、自然肤色、古铜色、蜜色、肤色偏暖、偏黄的皮肤

- 这些颜色如果参考图里确实有，**照样用 hex 写**，只是不用这些词命名。
- 负向段要排除某种肤色时也写具体：写"高饱和黄橙皮肤"，不写"小麦色"。

### 2.5 取样值超出 protocol 2.6.1 区间时

protocol 2.6.1 给了皮肤底色的建议区间（色相 12–32°、饱和度 15–38%、明度 80–97%）。按用户要求**颜色以参考图为准**：
取样值超出区间时**照实写，不为过区间改色**；`ref_palette.py` 会打出提示，在订单备注里记一句即可。

## 3. 正向段结构（七段，顺序不可换）

| # | 段落 | 写什么 | 注意 |
|-|-|-|-|
| ① | 参考图固定句 | `参考图是身份与画风的唯一权威，只改角度、构图与背景。` | 仅参考图模式。只有宿主后端（Agnes）写 `<image 1>`；其他后端一律写"参考图"，否则模型会把尖括号画成文字（E5） |
| ② | 风格锚点 | 取风格档案的手法描述（第 4 节） | 只写一套画风；不写质量词 |
| ③ | 角色 | "角色与参考图一致：" + 标志性特征 + **各部位颜色锚点** | 参考图模式下不再长篇复述发型细节，但**颜色锚点必须写**（实测不写颜色会漂） |
| ④ | 皮肤 | 第 2.3 节的三档锚点整句 | 直接用 `ref_palette.py --skin` 给的句子 |
| ⑤ | 角度与表情 | 目标朝向的具体描述 + 表情 | 见下方角度写法 |
| ⑥ | 构图取景 | 头顶留白比例 + 取景范围 | 必须是可量的比例，不能只写"镜头拉远"（W3） |
| ⑦ | 背景与画布 | 纯色背景 hex + 固定画布条款 | 末尾固定加 `square canvas, no border, no frame, no circular mask, edge-to-edge`（E4） |

**角度写法**

| 目标 | 写法 |
|-|-|
| 正脸 `front` | 正脸胸像：双眼都可见且水平对称，鼻梁居中，左右脸颊基本对称 |
| 朝左 `profile_left` | 接近正侧脸，鼻尖朝左、耳朵在右，只出现一只眼睛和一只耳朵，鼻梁另一侧不画第二只眼 |
| 朝右 `profile_right` | 接近正侧脸，鼻尖朝右、耳朵在左，只出现一只眼睛和一只耳朵，鼻梁另一侧不画第二只眼 |

- 表情：参考图表情要保留就写"表情与参考图一致（<具体表情>）"；要改就写具体表情，别和参考图冲突又不说明。

**构图写法**（固定句式，比例按发型选）

```
画布顶部留出画布高度 <A>%–<B>% 的纯色空白，含最长发尖（与帽顶）在内的全部内容位于该空白线以下，
头发与帽子不得与上沿、左沿、右沿相接；只取头部与肩部，肩线完整入镜。
```

- 长刺发、高发髻、帽子高的角色用 **12%–14%**；普通发型用 **8%–10%**（protocol §2.6）。

## 4. 风格锚点（tv-anime-cel）

风格档案 `references/styles/tv-anime-cel.json` 的 `prompt_anchor` 是中英混写的长句。中文后端用下面的中文版本：

```
1990 年代日本 TV 动画赛璐璐风格：平涂上色，硬边双色阶阴影，2–3 像素深棕描边（不是纯黑粗线），
无渐变、无喷枪、无镜面高光，低彩度年代色板，减少发丝与布料的细碎线条。
```

- 画风是"手法"，不是"好看"：写线条粗细与颜色、阴影层数、有无渐变、色板饱和度。
- 风格档案的 `prompt_forbidden`（3D 渲染、写实皮肤、厚涂油画、镜面高光、喷枪渐变、发丝细碎细节、纯黑粗描边等）
  放进负向段（第 5 节）。
- 其他风格档案照同样方式：从 `prompt_anchor` 里取手法描述，译成目标语言。

## 5. 负向段：按后端能力二选一

先查第 6 节的"负向词"列。

### 5.1 后端支持负向词（Qwen 系列）

- 写成**独立的 negative**：名词短语，用"、"连接，**不写"不要"**（W4）。
- 至少覆盖这几类（与 `compile_prompt.py` 的 FORBIDDEN 分类一致）：

| 类 | 例 |
|-|-|
| 角度 | 侧脸、四分之三脸、扭头、双眼高度不一致（正脸单）；正脸、双眼同时可见（侧脸单） |
| 多主体 | 第二个人物、其他角色、人物倒影（参考图里有别的角色时把它点名，如"皮卡丘"） |
| 文字标记 | 文字、字母、数字、水印、台标、图标、黑边 |
| 画框裁切 | 圆形画框、装饰边框、圆角遮罩、切掉头顶、切掉帽顶、切掉肩线、发尖出画 |
| 背景 | 实景背景、山、树、天空、渐变背景、光斑 |
| 画风 | 写实、照片、3D 渲染、厚涂、喷枪渐变、镜面高光（取风格档案 `prompt_forbidden`） |
| 颜色 | 要排除的颜色写具体，如"高饱和黄橙皮肤" |
| 结构 | 多余手指、畸形手、错位五官 |

### 5.2 后端不支持负向词（MiniMax-H3-Image、宿主后端）

- **negative 必须留空**（填了会被适配器丢弃，`check_prompt.py` 判错 E6）。
- 每一类禁止项改写成**完整否定句 + 正向替代**，追加到正向段末尾、画布条款之前。例：
  - "不要画成侧脸或四分之三脸，要正对镜头、双眼同时可见。"
  - "画面只有单人主体，不要出现第二个角色或倒影。"
  - "不要出现任何文字、字母、水印、台标、图标或黑边。"
- **不要**把名词原样塞进正向段（只写"水印"，模型会去画水印）。

## 7. 提交格式

写成订单目录下的 `prompt-input.json`（网页订单由服务端写入同名文件；命令行用 `--prompt-file`）：

```json
{
  "prompt_zh": "<正向段全文>",
  "negative": "<负向段；后端不支持负向词时为空字符串>",
  "prompt_source": "agent",
  "spec_version": "prompt-spec-v1",
  "backend": "modelscope-qwen-image-2.1",
  "palette_file": "palette.json",
  "notes": "<可选：取样值超出 2.6.1 区间等说明>"
}
```

- `generate.py` 只读 `prompt_zh` / `prompt_en` / `negative`，其余字段供追溯。
- 网页提交时把正向段、负向段分别粘进两个输入框；agent 通道直接调用 `POST /api/generate`，
  `positive` / `negative` 字段同上。
- 全文写完整，**不能出现省略号**（E2，`generate.py` 视为截断直接拒绝）。每段不超过 4000 字（E3）。

## 8. 自查：`check_prompt.py`

```powershell
cd F:\zxc\Project\sdz-ptah\skills\sdz-ptah-avatar
py -3 scripts\check_prompt.py --prompt-file <订单目录>\prompt-input.json --backend <后端 id>
# 文生图（不用参考图）加 --mode text2img
```

退出码 0 才提交。检查项：

| 代号 | 级别 | 内容 |
|-|-|-|
| E0 | 错误 | 正向段为空 |
| E1 | 错误 | 含禁用模糊色词（与 `generate.py` 同一词表） |
| E2 | 错误 | 含省略号 |
| E3 | 错误 | 任一段超过 4000 字 |
| E4 | 错误 | 缺固定画布条款 |
| E5 | 错误 | 参考图模式缺固定句；非宿主后端写了 `<image 1>` |
| E6 | 错误 | 后端不支持负向词但 negative 非空 |
| E7 | 错误 | 含质量堆叠词（杰作、高清、8K、masterpiece、best quality 等） |
| E8 | 错误 | 含权重语法 `(词:1.2)` 或生成端不支持的参数（精确 90°、同一 seed、--ar 等） |
| E9 | 错误 | 手写的色相/饱和度/明度与 hex 不符（偏差 >2） |
| W1 | 警告 | 没有 hex，或有 hex 没跟数值（"不超过 #hex"的高光上限写法除外） |
| W2 | 警告 | 写了皮肤但完整锚点少于 2 个 |
| W3 | 警告 | 没写可量的头顶留白比例 |
| W4 | 警告 | 独立负向段里写了"不要" |
| W5 | 警告 | 文生图模式却写了参考图固定句 |
| W6 | 警告 | 负向段含模糊色词 |
| W7 | 警告 | 后端不支持负向词，正向段里却没有任何否定句 |
| W8 | 警告 | 中文段里夹了大段英文 |

- `check_prompt.py` 通过不代表画面一定合格，它只保证提示词"写法合规"。画面是否合格仍看出图后的评分与人工核对。
- `generate.py` 的审计（E1、E2 两项）是最后一道闸；本脚本是提前自查，避免白跑一轮。

## 9. 完整示例：小智 · 正脸 · Qwen-Image-2.1


**换成 MiniMax-H3-Image 时**：negative 清空，把上面各类禁止项改写成否定句追加到正向段（第 5.2 节），
步数和 CFG 不传。

## 10. 常见错误对照

| 错误写法 | 问题 | 改成 |
|-|-|-|
| 暖调小麦色皮肤 | 模糊色词，审计拒绝 | 皮肤：底色 #DEBAA3（色相 23°、…）+ 暗部 + 高光上限 |
| 琥珀棕大眼 | 没实测，和参考图不符 | 深棕黑瞳孔 #413630（…）配白色眼白 |
| 镜头略微拉远，发尖完整入镜 | 不可量，实测压不住长刺发 | 画布顶部留出画布高度 12%–14% 的纯色空白…… |
| 杰作，高清，8K | 质量词压过风格词 | 删掉，写画风手法 |
| (red cap:1.3) | 在线接口不认权重语法 | 删掉，用颜色锚点和描述强调 |
| `<image 1>` 写给魔搭 | 尖括号被当成文字 | 改成"参考图" |
| MiniMax 填了 negative | 被丢弃，等于没写 | 清空，改写成否定句并入正向 |
| 正向段写"水印、文字" | 模型会画出来 | 支持负向就放负向段；不支持就写"不要出现任何文字、水印" |
| 帽前白 #E7EEE7（色相 30°…） | 手写数值与 hex 不符 | 抄 `ref_palette.py` 输出 |
